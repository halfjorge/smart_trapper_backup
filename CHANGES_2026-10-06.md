# Smart Trapper changes, 2026-10-06 (Claude)

Backup of everything before these changes: `_BACKUP_2026-10-06_before_claude\`
To undo: double-click `RESTORE_PREVIOUS_VERSION.bat`.

## Why runs were slow
On the 2026-07-23 "Creature" run (5 min 20 s total):
- 3 min 51 s: the bridge worked out each layer's ink colour in Python, because
  the panel's own colour sampling never worked ("sampled RGB: (missing)").
- 57 s: trapping engine.
- 29 s: exporting masks from Photoshop.

## What changed
1. **Engine (SmartTrapperB1/engine/src/main.rs + new fast.rs)**
   - Trap rules unchanged. Results are pixel-for-pixel identical to the old
     engine (checked on full-size test jobs with 6 different setting combos,
     0 pixels different).
   - About 4x faster (smarter math for the spread, each mask read once).
   - Writes `mask_colors.json` itself in seconds, so the bridge no longer
     spends minutes on it. Same colours as the bridge's method.
   - New check: `smart_trapper_b1 --compare-jobs <folderA> <folderB>`.
2. **Panel (UXP_Trapper/main.js)**
   - Run Trapper skips the broken colour sampling (saves time per layer).
   - Every run gets a fresh job folder. Before, after the first run the panel
     reused that same folder, so leftover files could mix into the next run.
   - A setting of 0 now stays 0 (e.g. Key trap pullback 0 used to become 1).

## Expected
Run Trapper on a job like Creature: roughly 1 minute instead of 5+.

## Panel settings (later the same day)
- The setting boxes are now one clear field each (before, only a thin strip
  inside the grey box accepted clicks).

## Name-matching fix (afternoon)
- Layers whose names contain " / : * ? < > | (e.g. "Light" Purple, Blue - ...MUSIC/HYBE...) were not
  matched to their ink colour, so their CLEAN layer was skipped and the original left showing. On BTS
  this left Blue without its cleanup growth under the Dark Purple hatching. Fixed in main.js.
- Layer edge at 0 no longer logs as NaN (log only).
- Previous panel version kept at _BACKUP_2026-10-06_before_claude\UXP_Trapper\main_before_namefix.js

## New optional button: Clean Colors (evening)
- Does the manual fix of Ctrl-clicking each layer and filling it with its main colour.
- For every visible layer except the paper (bottom) layer, including the key, it finds the
  majority colour of the solid pixels and refills the layer with it. Each pixel keeps its own
  transparency, so soft edges are still handled by Alpha threshold.
- Skips overlay layers (not Normal, or under 100% opacity/fill), gray layers (mostly
  semi-transparent pixels) and layers with no clear main colour, and says why in the Status box.
- The whole thing is one history step called "Clean Colors": one Ctrl+Z undoes it.
- Previous panel version kept at _BACKUP_2026-10-06_before_claude\UXP_Trapper\main_before_cleancolors.js

## Rule 10: traps no longer butt up to open edges (2026-10-07)
- New setting "Colour trap pullback (px)", default 2. When a colour traps under another colour,
  the trap now stops this many pixels short of that colour's open edge (where it meets paper or a
  colour below). Example: on Byrne, RED used to creep right to the edge of small GREY dots near the
  calendar; on a slightly off-register print those red slivers would show. 0 = old behaviour.
- The key's own setting (Key trap pullback) is unchanged. Results with all layers on are unchanged.
- Both the engine (main.rs) and the panel (main.js) changed, so run BUILD_AND_TEST_ENGINE.bat
  once, then click Reload on Smart Trapper. The build check should still say PASSED (it uses an
  older job, which keeps the old behaviour).
- Previous versions kept in _BACKUP_2026-10-06_before_claude: UXP_Trapper\main_before_buttcheck.js
  and SmartTrapperB1\engine\src\main_before_buttcheck.rs

## Round traps that follow their own colour (2026-10-07)
- New checkbox "Round traps (follow own colour)", on by default.
  - Traps now grow the same distance in every direction (before: square growth gave about 7 px on
    diagonals and corners, and tiny specks turned into 11x11 squares).
  - A trap under another colour stops where it gets closer to open paper (or a colour below) than to
    its own colour, so it ends flush with the end of a shape instead of wrapping around it (Sara's
    corner sketch). Traps under the key are not affected by this part.
- With all layers on the print looks the same; only hidden trap changes. On Byrne about 10% less
  trap overall (mostly the extra diagonal width), and none of it touches an open edge.
- Untick the box to get the old square traps. Older job folders keep square traps.
- Engine files changed (main.rs, fast.rs): run BUILD_AND_TEST_ENGINE.bat once, then Reload.
- Previous versions in _BACKUP_2026-10-06_before_claude: UXP_Trapper\main_before_round.js,
  SmartTrapperB1\engine\src\main_before_round.rs and fast_before_round.rs

## Close key halo (2026-10-09)
- New checkbox "Close key halo", OFF by default. For files where the line work (key) doesn't quite
  touch the colours, so a thin paper outline shows around the key (Phish).
- When on, paper gaps up to 2 px wide between a colour and the key are filled with that colour
  (the nearest one), and the normal trap then runs that colour under the key. Open paper and
  gaps between two colours are never touched.
- Phish check: 363,379 halo pixels filled. That covers 97% of what was filled by hand, with the
  same colour as the hand-trapped file in 99.8% of them, and nothing changed anywhere else. Most
  of the remaining 3% is at the cropped top edge of the example.
- Leave it off when the artist meant those thin paper lines.
- The engine (main.rs) and panel (main.js) both changed: run BUILD_AND_TEST_ENGINE.bat once, then
  click Reload on Smart Trapper.

## Round traps keep at least 1 px of overlap (2026-10-09)
- I re-checked every easy example on the current engine with your settings (results in
  TEST_RESULTS.md). One real problem turned up. The round-trap corner rule removed the trap
  wherever a third, lower colour was as close as the trapping colour, which left two colours
  butting with no overlap. It happened mostly as single pixels, all over DMB's dithered gradient
  (26,000 px), and a little in BTS, Byrne and Methane.
- **Fix:** round traps now always keep the first ring of trap (about 1 px) next to the colour.
  Butt joins are now 0 in every example. The cost is a little more 1 px trap at open edges
  (Byrne: 6,771 -> 8,449 px).
- Nothing changes with all layers on.
- The engine (main.rs) changed: run BUILD_AND_TEST_ENGINE.bat, then Reload. The panel help text
  for Round traps changed too.
- Previous versions are in _BACKUP_2026-10-06_before_claude: SmartTrapperB1\engine\src\main_before_minoverlap.rs
  and UXP_Trapper\main_before_minoverlap.js

## Safeguards for risky settings (2026-10-09)
- **Why:** a Byrne run imported no traps. Edge bias had been set to -1 by accident, which shrinks
  every colour by 1 px. Nothing touched anything else, so the engine made 0 traps, and the CLEAN
  layers would have printed with thin paper gaps everywhere.
- **The red box at the top of the panel** now also checks the settings and shows "CHECK SETTINGS"
  when one looks like a slip:
  - Edge bias below 0
  - Trap width 0 or over 12
  - Colour or key trap pullback not smaller than Trap width
  - Alpha threshold under 1 or over 200

  It updates by itself as you change the boxes. Run Trapper writes the same warning into the
  Status box. Nothing is blocked; it's a warning only.
- **After Run Trapper:** the Status box says how many traps the engine made. If it's 0, the
  progress bar says "Complete - but 0 traps", and the red box shows "LAST RUN MADE 0 TRAPS" with
  the likely cause.
- **Import Traps** with nothing to import now explains why ("the engine made 0 traps ... check
  Edge bias"), instead of just "No traps found in traps.json".
- Panel only (main.js): click Reload, no build needed.

## Key lines always trap, and pullback keeps 1 px of overlap (2026-10-09)
- **Why:** Byrne runs with Edge bias 0 showed cream outlines under the dark blue line work when
  the key was hidden. Your previous after file had colour under the key lines instead.
  - Cause: the client colours stop a pixel short of the key's soft edge. Edge bias 1 grows them
    across that pixel so they touch the key and get trapped under it. At 0 they never touch the
    key.
  - Measured: colour under 40% of the key area at Edge bias 0, vs 64% at 1. The previous after
    file has 68%.
- **Fix 1 (engine):** Edge bias values from 0 up to 1 are now treated as 1, the minimum.
  Negative values (a deliberate choke) are left alone. Byrne at Edge bias 0 now gets 67% under
  the key.
- **Fix 2 (engine):** Colour trap pullback no longer removes the last 1 px of overlap.
  - Byrne at pullback 2 had 20,937 px where colours met with no overlap. Now 0.
  - Traps near the open edges (e.g. red under the small grey dots) are still cut back to 1 px.
- **Panel:** the help text for Edge bias and Colour trap pullback explains this.
- Engine and panel both changed: run BUILD_AND_TEST_ENGINE.bat, then Reload.
- Previous versions are in _BACKUP_2026-10-06_before_claude: SmartTrapperB1\engine\src\main_before_pullring.rs,
  main_before_edgemin.rs, and UXP_Trapper\main_before_edgemin.js

## New tick box: "File has transparent / overlay layers" (2026-10-09, medium files)
For files with Multiply, Darken or other overlay layers, or layers under 100% opacity or fill (e.g.
Mempho, Helton). **Off by default. When it's off, nothing changes.** Easy files come out
pixel-for-pixel the same as before (checked on DMB and Phish, with the box off and on).

When you tick it:
- **Manual Progressive Knockout:** overlay layers no longer cut out the colours underneath them.
  The overprint (yellow over blue = green) is part of the art. The overlays themselves are still
  cut by the key and by any solid layer above them.
- **Run Trapper:**
  - No traps are made under an overlay. Under a see-through layer a trap shows as a darker 5 px rim.
  - Overlays still trap under the key and under solid layers, as normal.
- **Prepare Import:** the overlay colour's `COLOR__` group gets the original layer's blend mode
  (Multiply, Darken...) and opacity. Before, the new `CLEAN__` and trap layers came in as Normal,
  which turned the overprints into solid ink.
- **Red banner:** if a file has overlay layers and the box is off, the banner names them and
  reminds you to tick it.

Results, with the knockout and the box ticked (details in TEST_RESULTS.md):
- **Mempho:** visible change outside soft edges went from 2.2% of the print to 0. Colours under
  the overlays are kept 100%.
- **Helton:** 3.5% → 0, with the same result.
- **Overlays under the key:** about 6 px (p90), the same as before. Your hand files measure about 5.

Order on an overlay file:
1. Tick the box.
2. Manual Progressive Knockout (if you use it).
3. Run Trapper.
4. Prepare Import.
5. Import Traps.
