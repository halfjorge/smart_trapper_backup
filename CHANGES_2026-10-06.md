## Why runs were slow
On the 2026-07-23 "Creature" run (5 min 20 s total):
- 3 min 51 s: the bridge worked out each layer's ink colour in Python, because
  the panel's own colour sampling never worked ("sampled RGB: (missing)").
- 57 s: trapping engine.
- 29 s: exporting masks from Photoshop.

## What changed
1. **Engine (SmartTrapperB1/engine/src/main.rs + new fast.rs)**
   - Trap rules unchanged. Results are pixel-for-pixel identical to the old
     engine (checked on full-size test jobs with 6 different setting combos,
     0 pixels different).
   - About 4x faster (smarter math for the spread, each mask read once).
   - Writes `mask_colors.json` itself in seconds, so the bridge no longer
     spends minutes on it. Same colours as the bridge's method.
   - New check: `smart_trapper_b1 --compare-jobs <folderA> <folderB>`.
2. **Panel (UXP_Trapper/main.js)**
   - Run Trapper skips the broken colour sampling (saves time per layer).
   - Every run gets a fresh job folder. Before, after the first run the panel
     reused that same folder, so leftover files could mix into the next run.
   - A setting of 0 now stays 0 (e.g. Key trap pullback 0 used to become 1).

## Rule 10: traps no longer butt up to open edges (2026-10-07)
- New setting "Colour trap pullback (px)", default 2. When a colour traps under another colour,
  the trap now stops this many pixels short of that colour's open edge (where it meets paper or a
  colour below). Example: on Byrne, RED used to creep right to the edge of small GREY dots near the
  calendar; on a slightly off-register print those red slivers would show. 0 = old behaviour.
- The key's own setting (Key trap pullback) is unchanged. Results with all layers on are unchanged.
- Both the engine (main.rs) and the panel (main.js) changed, so run BUILD_AND_TEST_ENGINE.bat

## Key lines always trap, and pullback keeps 1 px of overlap (2026-10-09)
- **Why:** Byrne runs with Edge bias 0 showed cream outlines under the dark blue line work when
  the key was hidden. Your previous after file had colour under the key lines instead.
  - Cause: the client colours stop a pixel short of the key's soft edge. Edge bias 1 grows them
    across that pixel so they touch the key and get trapped under it. At 0 they never touch the

- **Fix 2 (engine):** Colour trap pullback no longer removes the last 1 px of overlap.
  - Byrne at pullback 2 had 20,937 px where colours met with no overlap. Now 0.
  - Traps near the open edges (e.g. red under the small grey dots) are still cut back to 1 px.

## New tick box: "File has transparent / overlay layers" (2026-10-09, medium files)
For files with Multiply, Darken or other overlay layers, or layers under 100% opacity or fill (e.g.
Mempho, Helton). **Off by default. When it's off, nothing changes.** Easy files come out
pixel-for-pixel the same as before (checked on DMB and Phish, with the box off and on).

When you tick it:
- **Manual Progressive Knockout:** overlay layers no longer cut out the colours underneath them.
  The overprint (yellow over blue = green) is part of the art. The overlays themselves are still
  cut by the key and by any solid layer above them.
- **Run Trapper:**
  - No traps are made under an overlay. Under a see-through layer a trap shows as a darker 5 px rim.
  - Overlays still trap under the key and under solid layers, as normal.
- **Prepare Import:** the overlay colour's `COLOR__` group gets the original layer's blend mode
  (Multiply, Darken...) and opacity. Before, the new `CLEAN__` and trap layers came in as Normal,
  which turned the overprints into solid ink.
- **Red banner:** if a file has overlay layers and the box is off, the banner names them and
  reminds you to tick it.

Results, with the knockout and the box ticked (details in TEST_RESULTS.md):
- **Mempho:** visible change outside soft edges went from 2.2% of the print to 0. Colours under
  the overlays are kept 100%.
- **Helton:** 3.5% → 0, with the same result.
- **Overlays under the key:** about 6 px (p90), the same as before. Your hand files measure about 5.

Order on an overlay file:
1. Tick the box.
2. Manual Progressive Knockout (if you use it).
3. Run Trapper.
4. Prepare Import.
5. Import Traps.

## New tick box: "Key traps follow the colour you see" (2026-10-13, Peteschaw)

zone, so that is what peeks out if the key prints off register. Example: Peteschaw olive prints
under blue and was trapped to blue, but a 1-2 px blue line sat between olive and the key, so blue

  current engine with the box off.

## Fixes: 50% layers and Close key halo with overlays (2026-10-14, DMB Luke Martin / Baltimore)
1. **Layers under 100% opacity are bitmapped at the right point.** The panel exports such a layer with
   its opacity baked into the pixels (a 50% layer's most solid pixel comes out at 50%), so the alpha
   threshold cut it at 70% of its artwork instead of 35%, and its strokes came out thinner. The engine
   now scales the layer back to full strength first. Only layers under 100% opacity or fill are
   touched, and only when their pixels really look baked.
2. **Close key halo never fills with an overlay colour** (with "File has transparent / overlay layers"
   on). On Baltimore it filled thin cream paper strokes beside the key with the 50% SHADOW PURPLE.
- Baltimore: SHADOW PURPLE on the client's paper 24,008 -> 6,569 px (the rest is normal edge
  bitmapping). Solid colours can still fill thin paper strokes when the halo is on (Layer 1: about
  25,000 px of cream highlights), so leave Close key halo off on art like this.
- All 5 other job folders: identical to the previous engine.
- Not tick boxes: these are fixes. Files with no layer under 100% opacity, and runs with the halo off
  or the overlay box off, come out exactly as before.

**Engine changed:** run `BUILD_AND_TEST_ENGINE.bat`, then click Reload on the panel. Step 3 will say
DIFFERENT if your latest job has a layer under 100% opacity (Baltimore does) - that is expected.

## One-button "Run Trapper" (2026-10-26, panel only - print output unchanged)
- **New big "Run Trapper" button does your whole routine:** Manual Progressive Knockout, make the traps,
  Prepare Import Structure, Import Traps, in that order. It uses the very same steps and settings as the
  separate buttons, so the trapped file is the same as clicking the four by hand.
- **Tonal inks ticked:** the knockout is skipped (grayscale builds aren't knocked out).
- **It checks before touching the file** and stops with "Nothing in your file has been changed" when: no
  file is open or it has under 3 visible layers; the file has already been trapped (COLOR__ / CLEAN__ /
  TRAP__ layers); the helper isn't running or the engine is missing; the file isn't RGB at 300 ppi; a
  setting looks wrong (e.g. Trap width 0); or the file has overlay layers but "File has transparent /
  overlay layers" isn't ticked.
- **If a step goes wrong** it stops, says which step, what has already been done to the file, and to step
  back in History. Smaller problems (a colour without a CLEAN layer, a trap layer that didn't import) are
  listed at the end under "Please check before printing". One pop-up at the end instead of four.
- **Two versions:** your copy keeps the four separate buttons under "Individual steps (for testing)" (the
  engine-only one is now called "Run Trapper (engine only)"). The co-worker's copy has only Run Trapper,
  Clean Colors and Cut Top Key; it is made from yours by `tools/dev/make_shared_copy.py`, so the two
