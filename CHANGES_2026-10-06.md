# Smart Trapper changes, 2026-10-06 (Claude)

Backup of everything before these changes: `_BACKUP_2026-10-06_before_claude\`
To undo: double-click `RESTORE_PREVIOUS_VERSION.bat`.

## Why runs were slow
On the 2026-07-23 "Creature" run (5 min 20 s total):
- 3 min 51 s: the bridge worked out each layer's ink colour in Python, because
  the panel's own colour sampling never worked ("sampled RGB: (missing)").
- 57 s: trapping engine.
- 29 s: exporting masks from Photoshop.

## What changed
1. **Engine (SmartTrapperB1/engine/src/main.rs + new fast.rs)**
   - Trap rules unchanged. Results are pixel-for-pixel identical to the old
     engine (checked on full-size test jobs with 6 different setting combos,
     0 pixels different).
   - About 4x faster (smarter math for the spread, each mask read once).
   - Writes `mask_colors.json` itself in seconds, so the bridge no longer
     spends minutes on it. Same colours as the bridge's method.
   - New check: `smart_trapper_b1 --compare-jobs <folderA> <folderB>`.
2. **Panel (UXP_Trapper/main.js)**
   - Run Trapper skips the broken colour sampling (saves time per layer).
   - Every run gets a fresh job folder. Before, after the first run the panel
     reused that same folder, so leftover files could mix into the next run.
   - A setting of 0 now stays 0 (e.g. Key trap pullback 0 used to become 1).

## Expected
Run Trapper on a job like Creature: roughly 1 minute instead of 5+.

## Panel settings (later the same day)
- The setting boxes are now one clear field each (before, only a thin strip
  inside the grey box accepted clicks).
- Settings are saved as soon as you change them and survive reloads/restarts
  (before, changes were lost on reload).
- New "? Explain settings" button shows what each setting does.
  (Photoshop panels don't support hover tooltips, so it's a button instead.)
- Checkbox text is readable and clicking the text toggles the box.

## Name-matching fix (afternoon)
- Layers whose names contain " / : * ? < > | (e.g. "Light" Purple, Blue - ...MUSIC/HYBE...) were not
  matched to their ink colour, so their CLEAN layer was skipped and the original left showing. On BTS
  this left Blue without its cleanup growth under the Dark Purple hatching. Fixed in main.js.
- Layer edge at 0 no longer logs as NaN (log only).
- Previous panel version kept at _BACKUP_2026-10-06_before_claude\UXP_Trapper\main_before_namefix.js

## New optional button: Clean Colors (evening)
- Does the manual fix of Ctrl-clicking each layer and filling it with its main colour.
- For every visible layer except the paper (bottom) layer, including the key, it finds the
  majority colour of the solid pixels and refills the layer with it. Each pixel keeps its own
  transparency, so soft edges are still handled by Alpha threshold.
- Skips overlay layers (not Normal, or under 100% opacity/fill), gray layers (mostly
  semi-transparent pixels) and layers with no clear main colour, and says why in the Status box.
- The whole thing is one history step called "Clean Colors": one Ctrl+Z undoes it.
- Previous panel version kept at _BACKUP_2026-10-06_before_claude\UXP_Trapper\main_before_cleancolors.js

## Rule 10: traps no longer butt up to open edges (2026-10-07)
- New setting "Colour trap pullback (px)", default 2. When a colour traps under another colour,
  the trap now stops this many pixels short of that colour's open edge (where it meets paper or a
  colour below). Example: on Byrne, RED used to creep right to the edge of small GREY dots near the
  calendar; on a slightly off-register print those red slivers would show. 0 = old behaviour.
- The key's own setting (Key trap pullback) is unchanged. Results with all layers on are unchanged.
- Both the engine (main.rs) and the panel (main.js) changed, so run BUILD_AND_TEST_ENGINE.bat
  once, then click Reload on Smart Trapper. The build check should still say PASSED (it uses an
  older job, which keeps the old behaviour).
- Previous versions kept in _BACKUP_2026-10-06_before_claude: UXP_Trapper\main_before_buttcheck.js
  and SmartTrapperB1\engine\src\main_before_buttcheck.rs

## Round traps that follow their own colour (2026-10-07)
- New checkbox "Round traps (follow own colour)", on by default.
  - Traps now grow the same distance in every direction (before: square growth gave about 7 px on
    diagonals and corners, and tiny specks turned into 11x11 squares).
  - A trap under another colour stops where it gets closer to open paper (or a colour below) than to
    its own colour, so it ends flush with the end of a shape instead of wrapping around it (Sara's
    corner sketch). Traps under the key are not affected by this part.
- With all layers on the print looks the same; only hidden trap changes. On Byrne about 10% less
  trap overall (mostly the extra diagonal width), and none of it touches an open edge.
- Untick the box to get the old square traps. Older job folders keep square traps.
- Engine files changed (main.rs, fast.rs): run BUILD_AND_TEST_ENGINE.bat once, then Reload.
- Previous versions in _BACKUP_2026-10-06_before_claude: UXP_Trapper\main_before_round.js,
  SmartTrapperB1\engine\src\main_before_round.rs and fast_before_round.rs

## Red file check at the top of the panel (2026-10-07)
- If the open document is not RGB or not 300 ppi, a red box at the top of the panel says so and
  how to fix it (Image > Mode > RGB Color, or Image > Image Size to 300 ppi; for bigger files it also
  says what Trap width would match 5 px at 300 ppi). It updates by itself every 2 seconds, so it goes
  away once the file is fixed. Run Trapper also writes the warning into the status log.
- Panel only (main.js): just click Reload, no build needed.
- Previous version: _BACKUP_2026-10-06_before_claude\UXP_Trapper\main_before_filecheck.js

## Default settings (2026-10-07)
- Round traps on, Colour trap pullback now defaults to 0 (Sara's choice). Your saved settings are
  unchanged; this only matters on a fresh install or after clearing settings.

## Trap layer names (2026-10-07)
- Trap layers are now named "TRAP__<colour>_under_<colour above>" (was "_over_"), e.g.
  TRAP__Light Blue_under_Peach. Panel only: click Reload. Jobs imported before this keep their old names.
